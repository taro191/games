ขึ้นโฮสต์จริง: อ่าน DEPLOY.md (Docker + HTTPS อัตโนมัติ) ก่อนครับ
หน้าเว็บ: / = หน้าแรก (Landing)  /play = ตัวเกมและเข้าสู่ระบบ

จ่ายตลาดอีสาน - เวอร์ชันโฮสต์เอง (พร้อมบัญชีผู้เล่น เล่นข้ามเครื่อง และ Login ผ่าน 500 Windows Thailand)

โครงสร้าง
  public/landing.html    หน้าแรก (Landing Page)
  public/index.html      ตัวเกม (ไฟล์เดียว)  เปิดที่ /play
  Dockerfile, docker-compose.yml, Caddyfile, DEPLOY.md, scripts/  ชุดขึ้นโฮสต์และสำรองข้อมูล
  public/fonts/          ที่วางฟอนต์ของตัวเอง (ดู fonts/README.txt)
  server/server.js       เซิร์ฟเวอร์ Node.js ไม่ต้องติดตั้งแพ็กเกจเพิ่ม (npm install ไม่จำเป็น)
  tools/mock-500w.js     ตัวจำลองระบบ Login ของ 500 Windows สำหรับทดสอบ
  .env.example           ตัวอย่างการตั้งค่า

เริ่มใช้งาน (ต้องมี Node.js 18 ขึ้นไป)
  1) cd isan-market-game
  2) node server/server.js        แล้วเปิด http://localhost:3000
  ตั้งค่าผ่านตัวแปรสภาพแวดล้อม หรือคัดลอก .env.example เป็น .env แล้วรัน  npm run start:env  (Node 20.6+)

โหมดเข้าสู่ระบบ (AUTH_MODE)
  local  อีเมล + รหัสผ่านของเกมเอง (ค่าเริ่มต้น)
  500w   เข้าได้ผ่าน 500 Windows Thailand เท่านั้น (ปิดสมัคร/ล็อกอินด้วยอีเมลทั้งหมด)
  both   ทั้งสองแบบ

ข้อมูลผู้เล่น: เก็บเป็นไฟล์ใน DATA_DIR (ค่าเริ่มต้น server/data) ผู้เล่นล็อกอินจากเครื่องไหนก็เห็นความก้าวหน้าชุดเดิม
ปุ่ม "ออกจากระบบ" อยู่ในแท็บ "ฉัน"  และมีปุ่มลบบัญชี+ข้อมูลทั้งหมดในหน้า "ข้อมูลและความเป็นส่วนตัว"

เชื่อม Login กับ 500 Windows Thailand
  เกมเป็นฝั่งผู้ขอ (OAuth2 Authorization Code + PKCE) ขอจากทีม 500 Windows:
   - Authorization URL, Token URL, UserInfo URL
   - Client ID และ Client Secret
   - ลงทะเบียน Redirect URI:  https://โดเมนของคุณ/auth/500w/callback
   - ชื่อฟิลด์ใน UserInfo ที่เป็นรหัสสมาชิกที่ไม่เปลี่ยน (ตั้งใน W500_ID_FIELD)
  แล้วตั้ง AUTH_MODE=500w พร้อมค่าตามใน .env.example
  สำคัญ: ตัวนี้ผมทดสอบกับตัวจำลองที่ทำตามมาตรฐาน OAuth2 เท่านั้น ยังไม่ได้ทดสอบกับระบบจริงของ 500 Windows
  ถ้า 500 Windows ใช้วิธีอื่น (เช่น LINE Login, ลิงก์พร้อมโทเค็นที่เซ็นแล้ว) ต้องปรับส่วน /auth/500w/ ใน server.js

ขึ้นระบบจริง
  - วางหลัง HTTPS (nginx / Caddy / Cloudflare) แล้วตั้ง COOKIE_SECURE=1 และ TRUST_PROXY=1
  - ให้ DATA_DIR อยู่ในที่ถาวร และสำรองข้อมูลสม่ำเสมอ
  - โหมด local ยังไม่มีการยืนยันอีเมลและการรีเซ็ตรหัสผ่าน ถ้าเปิดให้คนทั่วไป แนะนำใช้ AUTH_MODE=500w
  - การเก็บเป็นไฟล์เหมาะกับผู้เล่นหลักร้อยถึงหลักพันคน ถ้ามากกว่านี้ควรย้ายไปฐานข้อมูล
  - ข้อมูลส่วนบุคคลต้องปฏิบัติตาม PDPA หน้า "ข้อมูลและความเป็นส่วนตัว" เป็นคำอธิบายทั่วไปของตัวเกม ไม่ใช่นโยบายตามกฎหมาย
    ควรให้ผู้เชี่ยวชาญตรวจสอบก่อนเปิดให้คนทั่วไปใช้

ใช้แบบไม่มีเซิร์ฟเวอร์
  อัปโหลดเฉพาะ public/index.html ไปไว้ static host ได้ เกมจะบันทึกในเบราว์เซอร์ของผู้เล่น (ไม่ข้ามเครื่อง ไม่มี Login)

ความปลอดภัยที่มีให้
  รหัสผ่านเก็บแบบ scrypt + salt, คุกกี้เซสชันเซ็นลายเซ็น (HttpOnly, SameSite=Lax, 30 วัน), ป้องกัน CSRF ด้วยส่วนหัวเฉพาะ,
  จำกัดจำนวนครั้งการลองรหัสผ่าน, ส่วนหัว CSP, ป้องกัน path traversal, จำกัดขนาดข้อมูลที่บันทึก
