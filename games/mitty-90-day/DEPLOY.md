# นำ Mitty 90 Day ขึ้นโฮสต์ (ทางเลือกที่แนะนำ: เซิร์ฟเวอร์ VPS + Docker)

ภาพรวม:  ผู้เล่น → https://โดเมนของคุณ  →  Caddy (HTTPS อัตโนมัติ)  →  เกม (Node.js)  →  ข้อมูลผู้เล่นในโวลุ่ม /data

หน้าเว็บ:  `/` = หน้าแรก (Landing)   `/play` = ตัวเกม + เข้าสู่ระบบ   `/healthz` = ตรวจสถานะ

## ที่ต้องมี
1. เซิร์ฟเวอร์ Linux (เช่น Ubuntu 22.04/24.04) ที่เปิดพอร์ต 80 และ 443 ขนาดเริ่มต้นเล็กๆ (1 vCPU, RAM 512MB–1GB) เพียงพอสำหรับทดลอง
2. โดเมน (หรือซับโดเมน) ที่ตั้ง A record ชี้มาที่ IP ของเซิร์ฟเวอร์ (ตั้งให้เสร็จก่อน ไม่งั้นขอใบรับรอง HTTPS ไม่ผ่าน)
3. ข้อมูลจาก 500 Windows ถ้าจะใช้ AUTH_MODE=500w (ดูหัวข้อ "เชื่อม 500 Windows")

## ขั้นตอน (ราว 10 นาที)
```bash
# 1) ติดตั้ง Docker (ครั้งเดียว)
curl -fsSL https://get.docker.com | sh

# 2) อัปโหลดโฟลเดอร์นี้ขึ้นเซิร์ฟเวอร์ (scp / git) แล้วเข้าไปในโฟลเดอร์
cd mitty-90-day

# 3) ตั้งค่า
cp .env.production.example .env
nano .env            # แก้ DOMAIN, AUTH_MODE และค่า W500_* ให้ครบ

# 4) เริ่มระบบ
docker compose up -d --build

# 5) ตรวจ
docker compose ps
docker compose logs -f app
curl https://โดเมนของคุณ/healthz     # ควรได้ {"ok":true}
```
เปิด `https://โดเมนของคุณ` ควรเห็นหน้าแรก กด "เริ่มเล่นเลย" จะไปหน้าเข้าสู่ระบบ

## เชื่อม 500 Windows Thailand
ขอจากทีม 500 Windows แล้วใส่ใน `.env`:
- `W500_AUTH_URL`, `W500_TOKEN_URL`, `W500_USERINFO_URL` (OAuth2 Authorization Code)
- `W500_CLIENT_ID`, `W500_CLIENT_SECRET`
- ให้เขาลงทะเบียน Redirect URI เป็น `https://โดเมนของคุณ/auth/500w/callback` (ต้องตรงกับ `W500_REDIRECT_URI` ทุกตัวอักษร)
- ชื่อฟิลด์รหัสสมาชิกใน UserInfo → `W500_ID_FIELD` (ต้องเป็นค่าที่ไม่เปลี่ยน)

ทดสอบก่อนขึ้นจริงได้ด้วยตัวจำลอง: `npm run mock500w` (ดู .env.example)
ข้อควรรู้: โค้ดส่วนนี้ผ่านการทดสอบกับตัวจำลองมาตรฐาน OAuth2 เท่านั้น ยังไม่เคยเชื่อมกับระบบจริงของ 500 Windows
ถ้าเขาใช้วิธีอื่น (เช่น LINE Login) ต้องปรับส่วน `/auth/500w/` ใน `server/server.js`

## สำรองและกู้ข้อมูล
```bash
sh scripts/backup.sh                              # สร้างไฟล์ใน backups/ (เก็บ 30 ไฟล์ล่าสุด)
sh scripts/restore.sh backups/mitty-data-XXXX.tgz # กู้ข้อมูล
# ตั้งสำรองอัตโนมัติทุกคืนตี 3:   crontab -e   แล้วเพิ่มบรรทัด
# 0 3 * * * cd /path/to/mitty-90-day && sh scripts/backup.sh
```
ควรคัดลอกโฟลเดอร์ `backups/` ไปเก็บนอกเซิร์ฟเวอร์ด้วย (ไม่ควรเก็บแค่เครื่องเดียว)

## อัปเดตเกม
แทนที่ไฟล์ใน `public/` หรือ `server/` แล้วรัน `docker compose up -d --build` ข้อมูลผู้เล่นอยู่ในโวลุ่ม ไม่หาย

## ทางเลือกอื่น
- **Render / Railway / Fly.io:** สร้างเว็บเซอร์วิสจาก Dockerfile ในโฟลเดอร์นี้ แล้ว **ต้องผูกดิสก์ถาวร (persistent disk) ไปที่ `/data`**
  ถ้าไม่ผูก ข้อมูลผู้เล่นจะหายทุกครั้งที่ deploy ใหม่ ตั้งตัวแปร `COOKIE_SECURE=1`, `TRUST_PROXY=1`, `AUTH_MODE` และ `W500_*` ในหน้าตั้งค่าของบริการ
  (ไม่ต้องใช้ Caddy เพราะบริการเหล่านี้ทำ HTTPS ให้)
- **ไม่ใช้ Docker:** ติดตั้ง Node 18+ แล้วรัน `node server/server.js` ด้วย systemd และใช้ nginx/Caddy ทำ HTTPS ชี้ไปที่พอร์ต 3000
  ตั้ง `DATA_DIR` ไปที่ที่ถาวร, `COOKIE_SECURE=1`, `TRUST_PROXY=1`

- [ ] ทดลอง Login จริงด้วยบัญชี 500 Windows แล้วเล่นข้ามเครื่องได้
- [ ] ตั้งสำรองข้อมูลอัตโนมัติและทดลองกู้อย่างน้อย 1 ครั้ง
- [ ] ใช้ AUTH_MODE=500w (โหมดอีเมลยังไม่มียืนยันอีเมลและรีเซ็ตรหัสผ่าน)
- [ ] ให้ผู้เชี่ยวชาญตรวจเรื่อง PDPA และข้อความในหน้า "ข้อมูลและความเป็นส่วนตัว" (เป็นคำอธิบายทั่วไป ไม่ใช่นโยบายตามกฎหมาย)
- [ ] ให้คนจริง 5–10 คนลองเล่นบนมือถือ แล้วปรับตัวเลข XP/เครดิตตามผล

## ขีดจำกัดของเวอร์ชันนี้
- เก็บข้อมูลเป็นไฟล์ เหมาะกับผู้เล่นหลักร้อยถึงหลักพันคน ถ้ามากกว่านี้ควรย้ายไปฐานข้อมูล
- ใช้เซิร์ฟเวอร์เครื่องเดียว (ยังไม่รองรับการรันหลายเครื่องพร้อมกัน)
- ยังไม่มีหน้าแอดมิน และยังไม่มีกระดานคะแนนหรือเล่นร่วมกันหลายคน
